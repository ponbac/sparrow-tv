# Load Channel Icons in the Shield client

Client layouts can display the Channel Icon that an M3U Source names. Tauri delegates these requests to the WebView. The native Shield renderer will load the icons for its own visible rows and preview through a separate client. The Channel Catalog keeps the existing URL validation and Channel Icon selection.

The icon client accepts absolute HTTP(S) locations with a host and no credentials, including icons hosted on a provider's LAN. It follows up to five redirects after applying the same validation to each destination. Provider sources may use a separate CDN or a local hostname. Use anonymous GET requests with no referrer, cookies, authorization or Source headers, with Android's initialized platform certificate verifier for HTTPS. Keep the icon location and the network response out of diagnostics.

Shield uses the verifier's Android network security configuration to permit retrieval of signed revocation lists from its listed certificate authorities. Keep the Android artifact paired with the Cargo-selected verifier. Recheck the verifier and its allowlist if otherwise valid HTTPS icons start failing certificate revocation checks.

Use raster PNG, JPEG, the first frame of GIF, and simple opaque lossy WebP with a single VP8 chunk. Reject lossless and extended WebP, including transparent and animated WebP, before decoder initialization because the pinned decoder allocates lossless working storage outside its configured limit. A bounded dedicated lane limits elapsed time, simultaneous requests, streamed bytes and source dimensions before decoding. Android's synchronous certificate verification can hold a request past its deadline while fetching a revocation list. Decode and scale outside the render loop. Keep a byte-bounded memory cache, deduplicate visible requests and defer notifications during active D-pad movement. Account for both decoded data and the renderer's sprite allocation. Unsupported, missing and failed images show the existing Channel Number or placeholder, including SVG and AVIF in the development package.

Use synthetic HTTP(S) fixtures to prove the URL policy, anonymous redirect requests, bounded reads and decode, cache behavior and failure handling. Check fit in Now, Timeline and Search and record memory with real guide navigation during physical Shield acceptance. The existing no-icon comparison fixture remains useful for isolating the Guide cost.
